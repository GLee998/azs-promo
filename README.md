# Акция «Комбо Coca-Cola»: регистрация чеков

Тестовая версия сервиса для розыгрыша на АЗС. Клиент покупает 2 Coca-Cola и 2 френч-дога, получает машинку, сканирует QR на стойке и регистрирует чек. Маркетинг проверяет заявки в закрытом реестре и выдаёт номера участников.

Три отдельных сайта и API:

| Сайт | Папка | Для кого |
|---|---|---|
| Клиент | `web/client` | форма регистрации чека, правила, политика |
| Касса | `web/kassa` | очередь заявок, выдача машинки, ввод реквизитов чека |
| Админка | `web/admin` | реестр, розыгрыш, QR для касс, тестовые чеки |

Общие стили, картинки и клиент API лежат в `web/shared`. `./build.sh client|kassa|admin` собирает сайт в `dist/<имя>` с адресами из `API_URL` и `CLIENT_URL`.
Локально сервер отдаёт все три: клиент на `/`, касса на `/kassa/`, админка на `/admin/`.

## Как устроено

```
Клиент (телефон) ──► karavan.…  ─┐
Кассир (учётка АЗС) ► kassa.… ──┼─► Caddy (HTTPS, статика, /api/*) ──► API (FastAPI) ──► Postgres
Маркетинг (учётка) ─► admin.… ──┘
```

* **Фронтенд** (`web/`): статические страницы без сборщика, библиотеки и шрифты лежат в `web/shared/vendor`.
* **Бэкенд** (`backend/app.py`): FastAPI и Postgres (локально SQLite). Схема меняется миграциями Alembic (`backend/migrations`), сотрудники заводятся через `backend/manage.py`.
* **Прод**: один сервер с Docker Compose, см. [deploy/README.md](deploy/README.md).

### Как проверяются заявки

| Что проверяем | Как |
|---|---|
| Покупка была | Загрузка выгрузки продаж (CSV `fn;fd;fp;qty`) отмечает «покупка сверена» и число комбо в чеке |
| Чек не отправлен повторно | Чек определяется по ФН + ФД + ФМ (браузер читает их из QR на фото: формат ГНС КР `tax.salyk.kg/...?fn_number=&fd_number=&fm=` или короткий `fn=&i=&fp=`; иначе маркетолог вписывает вручную). Повторные заявки помечаются как дубликат, второй раз один чек допустить нельзя |
| Игрушка выдана | Загрузка выгрузки выдач (CSV `fn;fd;fp`) |
| Покупку не вернули | Загрузка выгрузки возвратов снимает заявку с розыгрыша и аннулирует номера |

Допуск возможен только когда реквизиты заполнены, покупка сверена, игрушка выдана и возврата не было. При допуске выдаётся по одному номеру участника (`CC-00001`…) на каждое комбо в чеке.

Клиенту при отправке всегда показывается «Заявка принята. После проверки чека вы получите номер участника», в том числе для дубликатов: спорные случаи решает маркетинг (просит оригинал или электронный чек).

## Запуск локально

```bash
python3 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt
cd backend && ../.venv/bin/python manage.py add-user admin --role admin   # печатает пароль
../.venv/bin/python manage.py add-user azs1 --role cashier --station 1
../.venv/bin/uvicorn app:app --port 8765
```

Открыть http://localhost:8765, касса — http://localhost:8765/kassa/, админка — http://localhost:8765/admin/ (логин и пароль из `manage.py`).

У каждого сотрудника личная учётка: у кассира своя АЗС, на неё отмечаются выдачи. Все выдачи, отмены, снятия и розыгрыш пишутся в журнал (админка → выгрузка `/api/admin/audit.csv`). Новый пароль: `manage.py set-password <логин>`, отключить: `manage.py disable-user <логин>`.

Тест сквозного сценария (регистрация, блокировки, касса, одновременная регистрация): `cd backend && ../.venv/bin/python test_app.py`

## Развёртывание

Свой сервер (VPS) с Docker Compose: Caddy, API и Postgres, бэкапы, мониторинг и тестовый стенд. Пошагово — [deploy/README.md](deploy/README.md).

Тесты: `cd backend && ../.venv/bin/python test_app.py`, `node --test web/client/*.test.js web/shared/*.test.js` и `bash deploy/tests/test_scripts.sh`.

## Настройки API (переменные окружения)

| Переменная | По умолчанию | |
|---|---|---|
| `DATABASE_URL` | `sqlite:///./promo.db` | для Postgres схему создаёт `alembic upgrade head` |
| `SESSION_TTL_HOURS` | `14` | сколько часов действует вход сотрудника |
| `SMS_REQUIRED` | `false` | требовать подтверждение номера |
| `DEMO_SMS` | `true` | не отправлять SMS, показывать код на экране |
| `WAITING_TTL_HOURS` | `3` | через сколько часов невыданная заявка освобождает номер и чек |
| `DRAW_PRIZES` | `8` | число призов в розыгрыше |
| `DRAW_RESET_ALLOWED` | `false` | сброс розыгрыша, только для тестового стенда |
| `RL_REG_IP`, `RL_REG_PHONE`, `RL_LOGIN_IP` | `60`, `5`, `10` | лимиты: регистраций с IP за 10 мин, попыток на номер за час, входов с IP за 15 мин |
| `DB_POOL_SIZE` | `10` | соединений с Postgres на воркер (плюс 5 запасных) |
| `SERVE_WEB` | `true` | API отдаёт и сайты (локально); в Docker выключено |
| `ALLOWED_ORIGINS` | `*` | CORS; за Caddy сайты и API на одном адресе, CORS не нужен |
